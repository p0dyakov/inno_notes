    Divide and Conquer

    Slide 5-8: Divide-and-Conquer Algorithms

    Divide-and-conquer algorithms consist of three parts: * Divide: How to reduce a problem for a large input to solving the same problems with smaller input sizes. * Conquer: How to solve problems for sufficiently small input sizes. * Combine: How to combine solutions for subproblems into a solution for the original (large) problem.

    Slide 9-10: Recurrence Relations

    Divide-and-conquer algorithms are a type of recursive algorithms. Therefore, we will first write the running time of such algorithms as a recurrence relation, which will need to be solved later.

    A recurrence relation can describe the running time of an algorithm in the base and recursive cases, for example: \[T(n) = \begin{cases} \Theta(1) & \text{if } n = 1 \\ T(n/5) + T(7n/10) + \Theta(n) & \text{otherwise} \end{cases}\]

    Slide 11-14: Approaches to Solving Recurrence Relations

    There are at least 3 methods for solving recurrence relations: 1. Substitution method: “guess” a bound and prove it by mathematical induction. 2. Recursion tree method: transform the recurrence relation into a tree and sum the complexity at each level of recursion, using methods for estimating sums. This approach is described in (Cormen et al. 2022, §4.4). 3. Master method: a general recipe for solving many recurrence relations of the form \(T(n) = aT(n/b) + f(n)\).

    Slide 15-18: Maximum Subarray Problem

    • Input: A sequence of \(n\) numbers \(\langle a_1, a_2, \dots, a_n \rangle\).
    • Output: Indices \(l\) and \(r\) such that \(\sum_{i=l}^r a_i \ge \sum_{i=l'}^{r'} a_i\) for any \(1 \le l', r' \le n\).

    Usage: 1. A simple variant of data analysis (time series). 2. Often the input array is obtained by processing absolute data (numbers are relative changes in price/temperature).

    [Handwritten Scribbles & Diagrams]: * Diagram: A long rectangular bar represents the array. Brackets highlight a central segment from \(l\) to \(r\). A blue \(\Sigma\) (sigma) is drawn above it. * Example Array: 2 -1 3 4 1 -5. * Calculations: * l points to -1, r points to 4. * Sums: -1, -1 + 3, -1 + 3 + 4 = 6. * Brute Force logic: for l = 1 to n for r = l to n for i = l to r [summation] * Note: Resulting complexity \(\Theta(n^2)\) (optimized).

    Slide 19-22: Maximum Subarray Problem (divide and conquer)

    Algorithm idea: * Divide: Find the maximum subarray on the left and right (from the middle). * Conquer: A singleton array is already maximal. * Combine: The maximum subarray is either * on the left (recursive calls) * on the right (recursive calls) * in the middle (crossing the middle). Note: “not a recursive call!”

    [Diagram]: Array shown with halves \(A_1\), \(A_2\), and a central crossing segment \(A_3\).

    Slide 23: Finding Maximum Crossing Subarray (pseudocode)

    FIND-MAX-CROSSING-SUBARRAY(\(A, low, mid, high\)) 1. left-sum = -∞ 2. sum = 0 3. for i = mid downto low 4. sum = sum + A[i] 5. if sum > left-sum 6. left-sum = sum 7. max-left = i 8. right-sum = -∞ 9. sum = 0 10. for j = mid + 1 to high 11. sum = sum + A[j] 12. if sum > right-sum 13. right-sum = sum 14. max-right = j 15. return (max-left, max-right, left-sum + right-sum)

    • Handwritten Note: Complexity is \(\Theta(n)\).
    • Diagram: Shows scan moving left from mid to low, and right from mid+1 to high.

    Slide 24: Maximum Subarray Problem (pseudocode)

    FIND-MAXIMUM-SUBARRAY(\(A, low, high\)) 1. if high == low 2. return (low, high, A[low]) // base case: only one element 3. else mid = floor((low + high) / 2) 4. (left-low, left-high, left-sum) = FIND-MAXIMUM-SUBARRAY(\(A, low, mid\)) 5. (right-low, right-high, right-sum) = FIND-MAXIMUM-SUBARRAY(\(A, mid + 1, high\)) 6. (cross-low, cross-high, cross-sum) = FIND-MAX-CROSSING-SUBARRAY(\(A, low, mid, high\)) 7. if left-sum >= right-sum and left-sum >= cross-sum 8. return (left-low, left-high, left-sum) 9. elseif right-sum >= left-sum and right-sum >= cross-sum 10. return (right-low, right-high, right-sum) 11. else return (cross-low, cross-high, cross-sum)

    [Handwritten Analysis]: * Line 1-2: \(\Theta(1)\) * Line 4: \(T(n/2)\) (recursive call) * Line 5: \(T(n/2)\) (recursive call) * Line 6: \(\Theta(n)\) (not a recursive call) * Line 7-11: \(\Theta(1)\) * Recurrence: \(T(n) = \begin{cases} \Theta(1) & \text{if } n=1 \\ 2T(n/2) + \Theta(n) & \text{otherwise} \end{cases}\)

    Slide 25-29: Algorithm Complexity Analysis

    • Divide: Division only requires finding the index of the middle of the array in \(\Theta(1)\). In this case, the size of each subarray is \(n/2\).
    • Conquer: For a singleton array, the search takes \(\Theta(1)\).
    • Combine: Compare the maximum for the left subarray, the right subarray, and the maximum crossing subarray, which we need to find separately in \(\Theta(n)\).

    Recurrence relation: \[T(n) = 2T(n/2) + \Theta(n)\] * Handwritten Note: (if \(n\) is small, \(T(n) = \Theta(1)\)) * According to the master theorem, we get: \(T(n) = \Theta(n \log n)\).

    File 2: Master Method (Slides 31-59)

    Slide 31-37: Master Method

    The master method allows solving recurrence relations of the form: \[T(n) = a T(n/b) + f(n)\] * \(a\): number of recursive calls (Constraint: \(a > 0\)) * \(n/b\): input data division (Constraint: \(b > 1\)) * \(f(n)\): divide and combine cost (Constraint: \(f(n)\) is asymptotically nonnegative)

    Simplified Notation: \(a T(n/b)\) stands for \(a' T(\lfloor n/b \rfloor) + a'' T(\lceil n/b \rceil)\) where \(a = a' + a''\).

    Slide 38: Master Theorem

    Theorem (Cormen et al. 2022, Theorem 4.1) Let \(a > 0, b > 1, f(n)\) be an asymptotically nonnegative function, and \(T(n)\) be defined by \(T(n) = aT(n/b) + f(n)\), then \(T(n)\) has the following asymptotic bounds: 1. If exists \(\epsilon > 0\) such that \(f(n) = O(n^{\log_b a - \epsilon})\), then \(T(n) = \Theta(n^{\log_b a})\). 2. If exists \(k \ge 0\) such that \(f(n) = \Theta(n^{\log_b a} \log^k n)\), then \(T(n) = \Theta(n^{\log_b a} \log^{k+1} n)\). 3. If exists \(\epsilon > 0\) such that \(f(n) = \Omega(n^{\log_b a + \epsilon})\), and the regularity condition holds (\(af(n/b) \le cf(n)\) for some \(c < 1\) and all sufficiently large \(n\)), then \(T(n) = \Theta(f(n))\).

    [Handwritten Note]: \(n^{\log_b a}\) is labeled “cost of recursion”. Note \(k+1\) circled in case 2.

    Slide 39: Recursion Tree Visualization

    [Handwritten Diagram Description]: A tree structure representing \(T(n) = a \cdot T(n/b) + f(n)\): * Level 0: \(f(n)\) * Level 1: \(a\) nodes, each \(f(n/b)\) * Level 2: \(a^2\) nodes, each \(f(n/b^2)\) * Base Level (1): Many \(\Theta(1)\) nodes. * Right margin: Sum of costs per level: \(f(n) + a \cdot f(n/b) + a^2 \cdot f(n/b^2) + \dots + a^{\log_b n}\). * Bottom bubble: labeled “cost of recursion” points to \(a^{\log_b n}\). * Derivation at bottom: \(a^{\log_b n} = n^{\log_b a \cdot \log_a n} = n^{\frac{\log_n a}{\log_n b}} = n^{\log_b a}\).

    Slide 40-44: Example 3.1

    Solve: \(T(n) = 2T(n/4) + 1\) * Proof: \(a=2, b=4, f(n)=1\). * \(n^{\log_b a} = n^{\log_4 2} = n^{1/2} = \sqrt{n}\). * To apply Case 1: show \(1 = O(n^{\log_4 2 - \epsilon})\). * Since \(\log_4 2 = 1/2\), choose \(0 < \epsilon \le 1/2\). * Result: \(T(n) = \Theta(\sqrt{n})\).

    Slide 45-49: Example 3.2

    Solve: \(T(n) = 2T(n/4) + \sqrt{n}\) * Proof: \(a=2, b=4, f(n)=\sqrt{n}\). * \(n^{\log_b a} = \sqrt{n}\). * To apply Case 2: show \(\sqrt{n} = \Theta(n^{\log_4 2} \log^k n)\). * Choose \(k=0\). * Result: \(T(n) = \Theta(\sqrt{n} \log n)\).

    Slide 50: Case 2 Logic (Handwritten)

    [Handwritten derivation]: If \(f(n) = \Theta(n^{\log_b a})\): \(T(n) = f(n) + a \cdot f(n/b) + \dots + a^{\log_b n}\) \(= n^{\log_b a} + a \cdot (\frac{n}{b})^{\log_b a} + \dots + n^{\log_b a}\) \(= n^{\log_b a} + a \cdot \frac{1}{b^{\log_b a}} \cdot n^{\log_b a} + \dots\) (Note: \(a \cdot \frac{1}{a} = 1\)) \(= \sum_{i=1}^{\log_b n} n^{\log_b a} = n^{\log_b a} \cdot \log_b n\)

    Slide 51-57: Example 3.3

    Solve: \(T(n) = 2T(n/4) + n\) * Proof: \(a=2, b=4, f(n)=n\). * \(n^{\log_b a} = \sqrt{n}\). * To apply Case 3: show \(n = \Omega(n^{\log_4 2 + \epsilon})\). Choose \(0 < \epsilon \le 1/2\). * Check Regularity: \(2(n/4) \le cn \implies n/2 \le cn\). * Choose \(c=1/2 < 1\). Condition holds. * Result: \(T(n) = \Theta(n)\).

    File 3: Merge Sort (Slides 60-93)

    Slide 60-63: Sorting in \(O(n \log n)\)

    Sorting Problem (Cormen et al. 2022, §1.1) * Input: Sequence \(\langle a_1, a_2, \dots, a_n \rangle\). * Output: Permutation \(\langle a'_1, a'_2, \dots, a'_n \rangle\) s.t. \(a'_1 \le a'_2 \le \dots \le a'_n\). * Notes: 1. Usually an array, but can be other data structures. 2. We sort complex objects; they are pairs of (key, satellite data).

    Slide 64-66: Key Ideas about Sorting

    1. Many quadratic (\(O(n^2)\)) algorithms work fast on small arrays due to efficient loops and processor cache (RAM model doesn’t account for this, I/O model does).
    2. In general, sorting cannot be faster than \(\Omega(n \log n)\) for comparison-based sorts.
    3. In special cases, linear time (\(O(n)\)) is possible.

    Slide 67-75: Merge Sort (overview)

    1. A divide-and-conquer algorithm.
    2. Runs in \(\Theta(n \log n)\).
    3. Stable.
    4. Not in-place (requires \(\Theta(n)\) additional memory).

    Algorithm Idea: * Divide: Split input array into two parts (halves). * Conquer: A singleton array is always sorted (no action). * Combine: Merge two sorted subarrays.

    Slide 76: Merge Sort (pseudocode)

    MERGE-SORT(\(A, p, r\)) 1. if p >= r 2. return // zero or one element? 3. q = floor((p + r) / 2) // midpoint of \(A[p \dots r]\) 4. MERGE-SORT(\(A, p, q\)) // recursively sort \(A[p \dots q]\) 5. MERGE-SORT(\(A, q + 1, r\)) // recursively sort \(A[q + 1 \dots r]\) 6. // Merge \(A[p \dots q]\) and \(A[q + 1 \dots r]\) into \(A[p \dots r]\). 7. MERGE(\(A, p, q, r\))

    Slide 77-88: Merge Example

    [Diagram Trace]: Merging [1, 4, 5, 6, 8] and [2, 3, 4, 7, 9]. * Step 1: Pick 1. * Step 2: Pick 2. * Step 3: Pick 3. * Stability point (Slide 81-82): Both arrays have a 4. * Handwritten Note: “It is important to prefer values from the left array to guarantee stability!” (Labeled Ivan for the left 4 and Artem for the right 4; Ivan comes first). * Final: [1, 2, 3, 4, 4, 5, 6, 7, 8, 9].

    Slide 89-93: Complexity Analysis

    • Divide: \(\Theta(1)\) (finding midpoint).
    • Conquer: \(\Theta(1)\) (singleton sort).
    • Combine: Merging total size \(n\) takes \(\Theta(n)\).
    • Recurrence: \(T(n) = 2T(n/2) + \Theta(n)\).
    • [Handwritten Analysis]: \(a=2, b=2, f(n)=\Theta(n), n^{\log_2 2} = n\). Case 2 applies.
    • Result: \(T(n) = \Theta(n \log n)\).

    File 4: Quicksort (Slides 94-126)

    Slide 94-102: Quicksort (overview)

    1. A divide-and-conquer algorithm.
    2. Runs in \(\Theta(n \log n)\) on average, but \(\Theta(n^2)\) in the worst case.
    3. Not stable.
    4. Efficient in-place implementation.

    Algorithm Idea: * Divide: Partition array into two parts (elements \(\le\) pivot and elements \(>\) pivot). * Conquer: Singleton array is sorted. * Combine: Concatenation (implicit).

    Slide 103: Quicksort (pseudocode)

    QUICKSORT(\(A, p, r\)) 1. if p < r 2. // Partition the subarray around the pivot, which ends up in \(A[q]\). 3. q = PARTITION(A, p, r) 4. QUICKSORT(\(A, p, q - 1\)) // recursively sort the low side 5. QUICKSORT(\(A, q + 1, r\)) // recursively sort the high side

    Slide 104-109: Partition Example

    [Diagram Trace]: Array: [4, 9, 5, 1, 4, 7, 3, 6, 8, 2]. Pivot is 5. * Left side (Low): [4, 1, 4, 3, 2]. * Right side (High): [9, 7, 6, 8]. * Combine: [4, 1, 4, 3, 2] [5] [9, 7, 6, 8]. * Sorted sub-results: [1, 2, 3, 4, 4] [5] [6, 7, 8, 9].

    Slide 110: In-Place Partition (pseudocode)

    PARTITION(\(A, p, r\)) 1. x = A[r] // the pivot 2. i = p - 1 // highest index into the low side 3. for j = p to r - 1 // process each element other than pivot 4. if A[j] <= x // does this element belong on low side? 5. i = i + 1 // index of a new slot in the low side 6. exchange A[i] with A[j] // put this element there 7. exchange A[i + 1] with A[r] // pivot goes just to the right of low side 8. return i + 1 // new index of pivot

    [Handwritten Diagram]: Array segments: * \(p \dots i\): \(\le x\) * \(i+1 \dots j-1\): \(> x\) * \(j \dots r-1\): \(??\) (unprocessed) * \(r\): pivot

    Slide 111-115: Complexity Analysis (Worst Case)

    • Divide: Partition takes \(\Theta(n)\). In the worst case, all elements (except pivot) go into one subarray of size \(n-1\).
    • Conquer: \(\Theta(1)\).
    • Combine: \(\Theta(1)\) (in-place).
    • Recurrence: \(T(n) = T(n-1) + \Theta(n)\).
    • [Handwritten Derivation]: \(T(n) \le T(n-1) + c \cdot n\) \(\le T(n-2) + c \cdot (n-1) + c \cdot n\) \(\le T(1) + c \cdot 2 + c \cdot 3 + \dots + c \cdot n\) \(\le c \cdot \sum_{i=1}^n i = c \cdot \frac{n(n+1)}{2} = O(n^2)\).
    • Result: \(T(n) = \Theta(n^2)\).

    Slide 116-120: Complexity Analysis (Best Case)

    • Divide: \(\Theta(n)\). Elements are divided into two subarrays of size \(n/2\).
    • Conquer: \(\Theta(1)\).
    • Combine: \(\Theta(1)\).
    • Recurrence: \(T(n) = 2T(n/2) + \Theta(n)\).
    • Result: \(T(n) = \Theta(n \log n)\) (by Case 2 of Master Theorem).

    Slide 121-125: Complexity Analysis (Average Case)

    • With random pivot, high probability of “large” subarrays.
    • Randomized quicksort is analyzed in (Cormen et al. 2022, §7.4).
    • Summary: Average \(\Theta(n \log n)\); Worst Case \(\Theta(n^2)\).

Case 3 \(\implies \Theta(n^2)\). 2. \(T(n) = 4T(n/2) + n^2 \implies a=4, b=2, n^{\log_2 4} = n^2\). Case 2 \(\implies \Theta(n^2 \log n)\). 3. \(T(n) = T(n/2) + 2^n \implies a=1, b=2, n^0 = 1\). \(2^n\) is much larger. Case 3. Regularity check: \(2^{n/2} \le c \cdot 2^n\) (ok for \(c=1/2\)). \(\implies \Theta(2^n)\). 4. \(T(n) = 2^n T(n/2) + n^2 \implies\) N/A (\(a=2^n\) is not constant). 5. \(T(n) = 16T(n/4) + n \implies n^2\) vs \(n\). Case 1 \(\implies \Theta(n^2)\).

    Slide 134: Problem 3.5

    Additional Master Method Practice: 1. \(T(n) = 2T(n/2) + n \log n\) (Case 2 with \(k=1\)) \(\implies \Theta(n \log^2 n)\). 2. \(T(n) = 2T(n/2) + \frac{n}{\log n}\) (N/A directly; \(\log^{-1} n\) isn’t polynomial diff). 3. \(T(n) = 2T(n/4) + n^{0.51}\) (Case 3 \(\implies \Theta(n^{0.51})\)). 4. \(T(n) = \frac{T(n/2)}{2} + \frac{1}{n} \implies a=1/2\) (Not Master theorem; \(a \ge 1\) required). 5. \(T(n) = 16T(n/4) + n!\) (Case 3 \(\implies \Theta(n!)\)).

    A. Yet Another Land of Mountains

    time limit per test: 0.5 seconds memory limit per test: 512 megabytes

    Heisenburger loves adventures. One day, he traveled to the Land of Mountains to conduct some exciting chemical experiments.

    He has a map of the land, represented as an \(N * M\) grid, where each cell corresponds to a mountain, and the value of the cell represents the mountain’s height.

    To feel safe, Heisenburger wants to choose a mountain that is shorter than all of its neighboring mountains (if a neighbor exists). Neighbors are the mountains directly above, below, to the left, and to the right.

    As his assistant, Jessie-Fries, you have been asked to find any safe mountain for Heisenburger.

    In this version, the map you have is not fully correct, so Heisenburger will give you \(Q\) queries to correct some heights.

    You must use divide and conquer to find the answer.

    Input

    The first line contains three integers, \(N\), \(M\) (\(1 \le N, M \le 2000\)), and \(Q\) (\(1 \le Q \le N * M\)) — the number of rows and columns of the grid, and the number of queries respectively.

    Each of the next \(N\) lines contains \(M\) integers \(h_{i1}, h_{i2}, ..., h_{im}\), representing the heights of the mountains in the \(i-th\) row of the grid (\(1 \le h_{ij} \le 10^5\)).

    Each of the next \(Q\) lines has three integers, \(i\) (\(1 \le i \le N\)), \(j\) (\(1 \le j \le M\)), \(k\) (\(1 \le k \le 10^5\)) — the row number, the column number, and the correct height of the given cell respectively.

    Note that no two neighbor mountains have the same height.

    Output

    Print two integers on a single line, the row and column indices of any safe mountain, separated by a space.

    Note that columns and rows are 1-based indexed.

    Example

    input

    4 4 2
5 2 1 7
10 6 5 3
1 4 7 15
21 17 32 40
1 2 7
1 3 8

    output

    1 1

    Note

    In the first test case, after changing cell in 1st row, 2nd column to 7, and the cell in the 1st row, 3rd column to 8, the cell \((1, 1)\) is a valid answer.

    Another possible answer can be \((3, 1)\)

    B. Nearest Restaurant

    time limit per test: 1 second memory limit per test: 256 megabytes

    Berland city is represented as a grid of \(N \times M\) blocks (1-indexed). There are \(K\) restaurants, each located at a distinct grid block. And there are \(P\) people, and each person wants to know which restaurant is closest to their location.

    The distance between two blocks is defined as the Euclidean distance: \[\sqrt{(X_i - X_j)^2 + (Y_i - Y_j)^2}\]

    You are asked to determine the nearest restaurant for each person using a divide and conquer Voronoi algorithm. To understand the intended approach, you may refer to: [Voronoi Visual Tool]

    You are NOT supposed to use dictionaries (including HashMap, TreeMap, std::ordered_map, std::unordered_map, or similar).

    Input

    The first line has four integers \(N, M, K,\) and \(P\) (\(1 \le N, M, K \le 100\)) and (\(1 \le P \le 1000\)) — representing the dimensions of the grid, the number of restaurants, and the number of people, respectively.

    Each of the following \(K\) lines contains a string \(S_i\) (\(3 \le |S_i| \le 20\)) and two integers \(X_i\) (\(1 \le X_i \le N\)) and \(Y_i\) (\(1 \le Y_i \le M\)) — representing the name and the coordinates of the \(i\)-th restaurant.

    Each of the following \(P\) lines contains two integers \(X_j\) (\(1 \le X_j \le N\)) and \(Y_j\) (\(1 \le Y_j \le M\)) — representing the coordinates of the \(j\)-th person.

    Restaurants’ names are unique and they may consist of English letter and “-”

    There can be at most one restaurant on each block.

    Output

    For each person, print the name of the nearest restaurant on a separate line.

    If multiple restaurants are at the same minimum distance, output the restaurant with the lexicographically smallest name.

    Example

    input

    4 5 3 3
Tubetei 1 2
Kstebi 2 3
Dodo-Pizza 4 3
2 3
2 1
3 3

    output

    Kstebi
Tubetei
Dodo-Pizza
